- 用户授权后，以 70 秒五次多项式关节轨迹展开到 J2≈80°、J3≈−60°、J5≈40°。实际跟踪正常；未发送模式、使能、夹爪或复位命令。路径在已有模型内采样检查，不能代替真实桌面/相机支架碰撞标定。
- 新执行层第一轮触发原始 Servo 速度加速度检查，净前进不足 1 mm。定位并修正检查顺序后，第二轮实机法兰位移 X +17.672 mm、Y +0.308 mm、Z +0.107 mm；最大朝向参考误差 0.190°，目标领先关节反馈最多 0.301°，处理回调 p95 2.22 ms。用户确认正确前进，但轻微抖动。
- 加入 150 ms 速度低通后第三轮实机：用户确认 X/Y/Z 都能移动，仍有轻微抖动。整段无轨迹拒绝，回调 p95 2.56 ms。输入包含多方向和两段 LB 会话，不把总净位移当作独立三轴直线精度标定。

- 所有本次写入进程已退出，输出租约已撤销。机械臂保持原有使能；没有使用导致阻尼下落的软急停或自动失能。

## 问题定位与修复

原桥接把 Humble Servo 的单周期位置直接当作 SDK 位置目标。Servo 每周期从实测状态构造下一步，在原故障日志中目标约领先 0.1°并反复停留，实测不动时目标也未推进。这是连续速度遥操作与位置 SDK 衔接不足的证据；尚未单独测定固件死区、内部插补或速度比例各自贡献。

`--execution-mode integrated-velocity` 增加显式执行层：Servo 关节速度 → 150 ms 低通 → 有限加速度 → 连续位置积分 → 最终目标守卫 → 独立 SDK worker 再检查 → JointCtrl。保留原 `servo-position` 默认模式供对照。

候选层检查名称、有限值、位置边界、速度及反馈领先；最终执行层和 worker 才检查实际发出的目标速度/加速度。第一轮发现旧顺序在平滑之前拒绝原始速度突变，现已用针对性回归测试覆盖。最终跟踪上限 1°、步长 1°、速度 0.15 rad/s、加速度 0.5 rad/s² 均未放宽；执行层使用 0.4 rad/s² 预留跨进程定时余量。LB 释放清空积分/滤波记忆，由 worker 请求已验证的实测位置保持。失联/过期/停滞会拒绝，不无限积分。

J1 诊断脚本原用原始左摇杆正号；现在与正式 joint 模式一致使用负号。没有翻转其他 Cartesian 轴。

## 验证与边界

32 项守卫、执行层和 ROS 消息测试通过。新增覆盖：带死区合成执行器持续推进、固定反馈触发既有跟踪上限、反向加速度约束、过期/重复关节名、速度波动衰减及“原始速度先平滑后守卫”的故障回归。

完整实际 Servo 模拟：360 输入、359 候选、0 拒绝，覆盖 X/Y/Z、Yaw 与 LB 释放。旧实机不动反馈日志回放时，积分后在既有 1°领先限制停止；这证明不会无界积累，不能预测换控制器后的实机运动。

当前证据证明短时间、低速 Cartesian 三轴遥操作恢复，**不证明抖动已消除、所有姿态均可用或完整示教采集已集成**。夹爪、相机、采集 UI 尚未接入这条 Servo 运动路线；模型仍是法兰控制点和 70 mm 夹爪模型，真实工具/桌面需另行标定。

现有数据导出采用下一时刻关节反馈为动作标签。轻微抖动会进入训练标签；先采 3–5 条进行图像清晰度、接触稳定性、静止漂移和动作序列检查，再批量采集。不要单独平滑动作而破坏图像/状态/动作的时间对应。

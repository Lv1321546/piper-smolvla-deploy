## 实机平移失败的证据

原始日志：`outputs/servo_bridge/20261023_supervised_xyz_01/events.jsonl`。全程 Servo 状态均为 `NO_WARNING`，没有奇异性、碰撞或边界停止。第一处桥接拒绝为 `Joint acceleration limit exceeded`，随后多次拒绝，SDK worker 最终因 `Input lease expired` 退出；已执行其现有、现场核对过的实测关节保持清理。

在第一处拒绝附近，J2 的 Servo 声明速度从约 0.01223 跳到 0.04491 rad/s，跨约 50 ms，超过 0.5 rad/s² 限制。该周期实际候选位置序列的差分加速度约 −0.151 rad/s²。Humble Servo 2.5.10 源码 `applyJointUpdate()` 使用 `(滤波后目标位置 − 当前测量位置)/周期` 声明速度，因此反馈变化会改变声明速度；不能把它直接等同于 SDK 实际执行的连续轨迹导数。

但不能只删掉声明速度加速度检查：同一日志全部候选按顺序、包含 SDK 0.001° 量化进行反事实差分审计，仍有 6 个相邻周期的位置差分加速度超过 0.5 rad/s²；声明速度差分有 16 处。该审计包含被拒绝/未发送候选，不是实际电机加速度测量。

第一处拒绝之前，法兰模型计算位移仅约 X +1.605 mm、Y +0.027 mm、Z −1.634 mm；用户未观察到预期水平移动。它同时存在执行跟踪不足和非目标方向变化，不能把超时修好就宣称 Cartesian 已恢复。目标反复只领先测量微小一步，可能受固件对小步位置目标的跟踪/运动规划影响；当前证据不足以断言是死区、速度百分比或某个电机参数。

Humble Servo 发布的是轨迹点，当前 SDK 桥只发送 JointCtrl 位置，忽略了轨迹速度/时间的执行语义。下一步应补齐并验证轨迹执行/跟踪层，使实际发送的位置、速度、加速度一致，保留真实反馈与跟踪误差边界。不能靠加速度阈值放大、提高速度或把合成反馈当作实测反馈绕过失败。可评估成熟的在线轨迹生成器或 ros2_control 轨迹执行接口；尚未部署或验证它们，也未发送任何 CPV/MIT 指令。
